# Omarchy theme integration

Omarchy Files reads the active Omarchy color contract from:

```text
~/.local/state/omarchy/current/theme/colors.toml
```

This is generated by `omarchy theme set`, so the application never reads or
modifies package-owned themes under `/usr/share/omarchy` and does not need to
guess the selected theme directory.

When the color source is set to **Auto**, the file is watched and takes
precedence over Dux Shell's optional color export. The mapping is deliberately
small and semantic:

| Omarchy token | Omarchy Files role |
| --- | --- |
| `background`, `foreground` | application surface and text |
| `accent` | primary action and focus color |
| `lighter_background`, `dark_background`, `darker_background` | elevated and nested surfaces |
| `selection`, `selection_foreground` | selected rows and their text |
| `muted` | secondary text and outlines |
| `red`, `yellow`, `cyan`, `green` | error, warning, informational, and success states |

If the file is missing, incomplete, or the user chooses a preset/custom color
source, Omarchy Files falls back to its existing preset and optional Dux Shell
paths. Theme synchronization therefore cannot block startup.

Typography and spacing remain application settings for now. They are not read
from Omarchy's shell configuration because that configuration controls shell
surfaces rather than ordinary application windows.
